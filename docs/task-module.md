# 任务模块

## 功能

两端支持列表、状态看板、截止日期日历和项目进度；支持标题/备注搜索、项目、负责人、状态、优先级、截止时间筛选及排序。编辑采用侧边抽屉，保存失败保留输入。批量支持状态、负责人及删除，最多 100 项，逐项反馈失败。

## 权限与接口

任务读写以 Spring `/api/tasks` 为唯一规则来源。Desk 使用自身 Cookie 鉴权后转发 Bearer Token，保留 `{tasks: []}` 列表响应，与项目详情兼容；Console 继续使用原有同源代理。

- 管理员可管理全部任务；成员只读团队任务和自己的个人任务。
- 创建人或管理员可编辑、删除、分配；团队任务的负责人额外允许仅更新 `status`。
- 个人任务不能指派给其他人。个人项目中的任务不能公开；项目和负责人均在服务端验证。
- `/api/tasks/members` 只返回有效账号的 ID 和显示名，不返回其他用户资料。
- 成员看不到 Desk 的定时任务管理标签；原有调度功能保持独立。

日任务沿用 HH:mm，单次和周任务使用 yyyy-MM-dd。日任务在日历中只显示于今天，不自动重置状态或重复创建。开始时间不得晚于截止时间；日期在服务端严格校验。重复提交“已完成”不重置完成时间，重新打开会清空完成时间。

## 部署

本次必须同时更新 Java 后端与两端前端，先启动后端，确认 `TaskAssignmentMigrator` 成功新增可空 `assignee_id`（以及兼容旧库所需的 start_date/period），再发布前端。迁移仅补列，不删除或重置数据。执行前备份数据库；迁移失败会阻止新后端就绪。

本地 `/preview?view=tasks` 提供内存交互演示，仍受本地预览登录和开发环境限制；刷新恢复示例，不调用真实任务 API。

## 验证

- `npm run check:tasks`：筛选、日期、负责人权限，以及两端模型一致性。
- 后端目录 `mvn test`：任务权限、参数校验、清空字段、状态时间、部分失败回归。
- 两端分别 `npm run build`。

两端 TaskWorkspace / task-model 的行为应同步修改，项目保持独立构建。
