# 模型输入、输出与超时

工作台「AI 助手 → 网关设置 → 输入输出」和管理后台「AI 网关 → 编辑」共享 `ai_config` 的三个字段，仅管理员可修改。

| 字段 | 设置范围 | 0 的含义 |
| --- | --- | --- |
| `max_input_tokens` | 0–2,000,000 | 不额外限制输入，仍受模型自身上下文窗口限制 |
| `max_output_tokens` | 0–262,144 | MiniMax 使用 16,384，其他模型沿用调用场景默认值 |
| `timeout_seconds` | 0–600 秒 | MiniMax 使用 240 秒，其他模型沿用调用场景默认值 |

输入预算为本地保守估算：序列化输入中的 ASCII 字符每 3 个估计 1 token，其他字符每个估计 2 tokens；不是模型 tokenizer 的精确计数。输入包含历史对话、系统提示词、知识引用；工具对话还包含工具定义及已返回结果。超限直接提示，不自动丢弃历史内容。

显式输出上限优先于自动值，包含推理内容与正式回答；设置过小仍可能导致截断。实际可用上限受模型提供方约束。超时用于该次模型请求，工具会话使用整体期限；用户停止仍立即中止请求。

MiniMax 采用 `reasoning_split: true` 分离思考与正文。兼容返回 `<think>` 的网关时，先过滤思考，再解析草稿，避免思考中提及的产物标签误删正式回答或变成可保存草稿。流式等待正文期间每 15 秒发送保活事件。

Java 启动时通过 `AiLimitsMigrator` 增量补充三个默认值为 0 的列；不覆盖旧模型、密钥和业务记录。部署顺序为先更新 Java 和数据库，再发布两个前端。

协议参考：[MiniMax OpenAI 兼容接口](https://platform.minimax.io/docs/api-reference/text-openai-api)。
